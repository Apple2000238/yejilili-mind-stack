# Continuity architecture

Nocturne is organized around one question:

> What must survive so that a later AI process can meaningfully continue an
> unfinished trajectory rather than merely reread a transcript?

## Continuity loop

```text
encounter
  → hold / analysis
  → Markdown memory + structured traces
  → decay, linking, latent fermentation
  → breath / trace / reverie
  → next context receives a selective continuity bundle
  → new encounter leaves a new difference
```

## Layers

### Memory substrate

`BucketManager` stores source-preserving Markdown records with YAML metadata.
Records may be dynamic, permanent, felt, unresolved, resolved, pinned, or
archived. They remain inspectable without the server or a model provider.

### Retrieval and continuity

- **Breath** assembles a selective bundle for a new or compacted context.
- **Trace** follows related records and chronological differences.
- **Reverie** permits looser recombination without replacing sources.
- **Constellations** exposes relationships among memory records.
- **Axis Fragments** keeps partial orientation rather than forcing certainty.
- **Echoes** preserves replayable external or voiced material when configured.

### Drives and differential processing

Drive analysis and DP traces retain slow-changing tendencies across turns.
The public edition keeps generic Drive Ledger and Thought Pool mechanics,
including Drift's NA, PA, and longing dimensions. Household-specific Atmosphere
and Gravity semantics are deliberately excluded.

### Fermentation

Thoughts, latent fragments, and dreams are derived layers. They must remain
traceable to stored inputs and must not silently become biographical fact.

## Invariants

1. Source memories remain readable and distinguishable from generated material.
2. Retrieval is selective; continuity is not transcript replay.
3. Uncertainty and unfinished threads may remain unresolved.
4. Identity and relationship prose belong to local data/configuration, not the
   reusable source tree.
5. The public edition must run immediately after installation.
6. Removing household layers must not break the memory, Dashboard, or MCP loop.
